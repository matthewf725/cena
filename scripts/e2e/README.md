# Local browser E2E

Run `pnpm test:e2e` after starting the local Supabase stack and applying the normal schema and seed. The runner never resets the database. It verifies that Supabase REST, Auth, and Mailpit are reachable, provisions unique disposable `@cena.test` accounts and a one-use promo, and uses a loopback-only fake Stripe processor. No real Stripe or external HTTP requests are used by the browser.

The runner builds the Go API at a stable path under `artifacts/e2e/bin` and binds it to `127.0.0.1` on port 8180. It starts fresh customer and restaurant previews on ports 8081 and 8082. Set `CENA_E2E_API_PORT`, `CENA_E2E_CUSTOMER_PORT`, or `CENA_E2E_RESTAURANT_PORT` if a port is occupied. Metro defaults to two workers. Set `CENA_E2E_METRO_MAX_WORKERS` to another positive integer if needed. The runner stops its own processes after each run. Supabase API defaults to 54323 and Mailpit to 54324.

Chromium is the default. Set `CENA_E2E_BROWSERS=chromium,webkit` to run both installed engines. Install engines with `pnpm exec playwright install chromium webkit`. Use `CENA_E2E_HEADLESS=0` to view the browser. Screenshots and a redacted run report are written under `artifacts/e2e/` (ignored by Git). The Supabase CLI status output and credentials are kept in memory and are never printed.

Coverage includes merchant sign-in, fake Connect readiness and fee display, promo creation, customer email OTP/profile persistence, bag persistence, incorrect checkout OTP recovery, invalid/valid promo quote cents, late promo and stock rejection/recovery, pending checkout visibility and idempotent replay, pending cancellation/release, fake payment with signed webhook, paid order state and fee/account snapshots, merchant accept/prepare/ready, payment-safe cancel guard, refund confirmation guard, fake refund, and customer history.
